# Advantage Deep Security Scan

Read the [Advantage execution context](../vulnops-advantage-security-scan/references/advantage-context.md)
first. Preserve fresh perspectives and one consolidation within the native global
allocation; do not create recursive scans.

## Bound invocation

Use **Shared top-level entry** in the shared context reference. Inside OMP the
controller selects
`python3 scripts/init-advantage.py --in-session [<completed-audit-path-or-run-id>] --mode deep`.
Deep/full are canonical defaults; preserve an explicit `--depth <depth>` override.
Terminal startup is documented only in that shared entry contract.
`vulnops-advantage-investigation` owns all passes inside that one execution.
An assigned investigator receiving this skill performs only its packet; it cannot
initialize top-level work, invoke a launcher, create a child scan, extend a deadline,
or delegate. Actions-only mode never enters deep review.

Inputs are all available historical baseline intelligence, current source and
repository inventory, accepted plan, immutable pass/wave ownership, context
permissions and resolved budget. Read usable canonical cohorts through the
catalog rather than capped report arrays; unavailable cohorts remain unknown.
No pass may modify source,
baseline, another pass's output, or its own published packet/result.

## Independent initialization, bounded work

1. Use `budget.deep_passes` and the plan's pass IDs. Each pass starts in fresh
   worker context with the same baseline identity and authorized source scope;
   no initial pass receives another pass's hypotheses or unpublished results.
   Vary the justified perspective across forward flows, backward capability
   consumers, identity/state transitions, or plausible alternative routes.
2. Allocate `max_tasks` and `max_questions` across all passes, not per pass.
   Balance high-value actors and boundaries without requiring every capacity
   slot to be used. Explicitly record intentional independent allocations of the
   same question; repetition is not newly established evidence.
3. Dispatch canonical native investigators within `max_concurrency`, using
   immutable waves/packets and current-invocation task coordination.
   Preserve current consumption and deferrals. Carry stable pass/task/question
   IDs and inherited native deadlines. Keep outcomes under
   `investigation/passes/<pass-id>/results/<task-id>.json`. Waves retain analytical
   predecessor relationships, not resumable scheduler authority.
4. Require terminal execution plus schema-valid yields and valid packet-bound
   artifacts before counting a result. Do not consume partial or unvalidated
   peer work. Capture both confirming paths and strongest contrary evidence.
5. Consolidate admitted eligible claims from completed publications and preserve
   terminal failed-assignment accounting under the shared contract. A local
   defect in one pass does not cancel unrelated active passes. Similar stories
   do not establish a shared root: compare the exact failed control, independently
   reachable operations, repair boundary and terminal impact. Preserve source
   anchors and exact question outcomes, including no-candidate results.
6. Use the native continuation builder only for a validated evidence delta or
   justified new actionable alternative with reserve left. Additional rounds,
   tasks/questions and the shared experiment envelope remain global, while live
   concurrency/deadlines bound optional retries. No multiplication by pass count or blind retry of a
   missing external prerequisite.
7. Finalize investigation once, then allow the one synthesis and fresh final
   verification sequence. Actual failures never authorize manufactured completion
   or automatic replacement invocations. Another explicit request starts fresh.

## Honest terminal accounting

Fresh context reduces anchoring but does not make passes independent of their
shared baseline or model. Agreement cannot prove an inherited assumption; the
final verifier challenges every inherited condition material to impact.

For every allocated question retain established facts, counterevidence, missing
facts, reason and next action. Apply the shared failure boundaries: allocation
preventing unstarted work is budget deferral; actual failed/cancelled native work
can be execution failure. Missing or unusable output otherwise leaves precise
`locally_unresolved` proof, never clean coverage or an invented execution.
Discard unusable evidence and continue healthy work through reporting without
mandatory retry, exhaustion proof or bookkeeping reconciliation. Existing global
limits are ceilings, not attempt quotas; no extra pass or cleanup pool. Cancel
all owned running work only for top-level failure or execution-wide safety faults.
The native finalizer owns canonical aggregation; this skill never writes another
report or claims exhaustive coverage.
