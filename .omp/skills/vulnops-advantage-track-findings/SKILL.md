# Advantage Track Findings

Read the [Advantage execution context](../vulnops-advantage-security-scan/references/advantage-context.md)
first. Preserve completed-source admission, exact selected identities, disclosure
minimization and reviewable payloads. Provider discovery, duplicate searches,
credentials, connector calls, external writes and readback are not part of this
native offline action.

## Explicit selected input

Only repeatable `--track-finding <finding-id>` requests select tracking. Never
export all findings because a scan succeeded or because tracking appears in the
skill inventory. The native handoff finalizer deterministically resolves exact
accepted findings and prepares the output; no model-generated ticket body can
replace the authoritative dossier.

After reading a completed Advantage report and receiving explicit selection, use
**Shared top-level entry** in the shared context reference. Inside OMP:

`python3 scripts/init-advantage.py --in-session [<original-audit-path-or-run-id>] --mode actions --action-source <completed-advantage-base> --track-finding <finding-id>`

Only the controller initializes this request; assigned workers never launch a new
execution. Preserve explicit depth (otherwise full) and all selected options.
Terminal startup remains in the shared entry contract, not a nested launcher.

The additional source must be completed, non-actions, and linked to that same audit.
Both source bundles remain unchanged, without file/hash attestation or historical
revalidation. IDs are scoped by execution, not matched by title, file or local ID
alone. Rejected, wrong-source or invalid selections fail admission; do not
substitute a nearby accepted finding. For an already admitted exact selection
whose accepted record is unavailable, use the shared contract's deterministic
`assessment_status: locally_unresolved` tracking record and explicit limitation,
not fabricated dossier content. Unrelated selected records continue. Preserve
historical scope rather than claiming current exploitability.

## Prepare a faithful offline handoff

1. Resolve each selection against the canonical final findings and available source
   records, not Markdown, partial display arrays, memory or draft candidates.
   Read the complete accepted dossier and available evidence closure for context.
2. Preserve stable execution/finding identity, original assessment scope, baseline
   relation, canonical source references, affected locations, source view and attacker prerequisites,
   impact limits, root-control explanation, remediation guidance and proof basis.
   Reused baseline primitives stay attributed rather than presented as new bugs.
3. Keep source locations repository-relative and role-aware. Do not fabricate
   commit links from remote names or claim externally verified version/audience
   facts. A source-only result remains source-only; no dynamic claim may be
   inferred from finding acceptance or an application check.
4. Remove secret values, credentials, signed URLs, author-machine paths,
   raw reproduction output, irrelevant private context and unreviewed links.
   Keep necessary disclosure limitations explicit. Use the existing sanitizer;
   do not erase the evidence identity or misrepresent redaction as proof loss.
5. Treat disclosure audience, provider, account, destination, and duplicate
   decision as matters for a separately authorized publication workflow. This
   execution cannot discover them online, claim a duplicate search, create an
   issue/advisory, select an account, or grant publication permission.

## Native output and terminal accounting

The selected tracking slot is generated by
`python3 scripts/finalize-advantage-handoff.py <advantage-base> --context <context>`
from authoritative accepted findings. Follow the native `advantage-action`
schema and paths in the shared reference, including exact selected-record
accounting. Do not hand-author provider receipts or edit the source bundles.
Unrequested tracking closes `not_selected` with no records; requested tracking
must retain exact selected-record accounting, including explicit unavailable
records, never silently succeed empty. An unavailable record is not a prepared
finding payload or a published tracking claim.

Return only the canonical handoff/report references, selected identities,
prepared count and disclosure limitations. Say **prepared for offline review**,
never **ticket created**, **published**, **synced**, or **provider verified**.
External publication requires a separate workflow with destination/audience
checks, duplicate reconciliation, exact payload review and fresh authorization;
none is inferred from this handoff.
