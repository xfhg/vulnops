# Advantage Validation

Read the [native Advantage context](../vulnops-advantage-security-scan/references/advantage-context.md)
first. When assessing an assigned candidate or sibling operation, read
[candidate validation](references/candidate-validation.md); for source-based
proof, read the shared
[static assessment](../vulnops-self-verification/references/static-assessment.md).

## Inputs and owner

The assigned `vulnops-advantage-investigator` uses its immutable packet,
candidate identities and locations, complete historical baseline catalog, current
source, and the shared permission/attempt/assessment envelope. Preserve
all supplied candidate fields and original dispositions. No new task pool or
standalone report is created. Fresh final verification uses the same evidence
method but remains a separate review, not the discoverer's self-approval.

## Method and execution boundary

Define up to five falsifiable claim criteria, prove each assigned concrete
instance through its real interface and closest control, challenge counterevidence,
and preserve unresolved facts without dropping eligible neighbors. One
representative proof or safe sibling does not settle other operations.
Use `skill://vulnops-self-verification` and `skill://vulnops-exclusion-rules`
for reportability, and `skill://vulnops-severity-guidance` when rating impact.

Request a material experiment only through the owning coordinator's native
request, reservation, safe wrapper and sanitized observation path. Debug builds,
ASan, debugger traces, tests and application imports are target execution:
never run them directly, on the host, with credentials, or by installing tools.
Off mode, unsupported containment or exhausted allocation means source-only.
Do not retain raw proof logs or assign confidence from a numeric tool shortcut.

## Output and resolution

Use the native candidate `reason` and question `resolution` fields for dispositions.
Record actual source/contained method, inspected evidence, tests truly run,
counterevidence, uncertainty, and the smallest discriminating next step. Preserve
candidate, seed, baseline, objective/question, root-control, sink, and concrete
instance identities throughout. No candidate disappears because another has a
cleaner story. `established` settles only the scoped question, not a final finding
or achieved objective. Distinguish `contradicted`, `locally_unresolved`,
`externally_blocked`, `budget_deferred`, and `execution_failed` as required by the
schema. Unexecuted examples remain predictions; sanitized observation references
are required for claims of actual contained execution.
